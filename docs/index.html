        Everything around the database

        One tool instead of six.

        Teams usually stitch together a SQL client, a migration tool, a scheduler, a monitoring dashboard, an audit export and a spreadsheet of who has access. Comb ships all of it, sharing one permission model and one audit trail.

        For developers

        Gets out of your way

        • ⌘K jumps to any table, saved query or screen. ⌘↵ runs the statement under the cursor.
        • Grid edits are staged, shown as SQL, then applied in one transaction.
        • Autocomplete from the live catalog, error positions, notices and CSV export.
        • Versioned migrations with dry runs, drift detection and rollbacks.
        • Cron-scheduled SQL with retries, delivered to Slack, Teams or a webhook.
        For managers and security

        Answers "who did what" in seconds

        • Every statement, login and change, with before and after row images for writes.
        • Four-eyes approvals on the connections you choose, with a rolled-back dry run first.
        • PII classification and server-side masking on results, exports and the audit trail.
        • Compliance controls with evidence, data-subject requests and retention policies.
        • Usage and cost by team, with a chargeback CSV.
        How it works

        One process, one metadata database, nothing else to run.

        No broker, no cache

        Background work runs on pg-boss, a queue stored in the metadata database. There is no Redis to operate.

        A real parser, not regexes

        Statements are classified with libpg-query, PostgreSQL's own parser. Comments, quoting or casing tricks can't slip a DROP past it.

        Your database role is the ceiling

        Comb only narrows what the stored database user may do, never widens it. Give each connection a least-privilege role.

        Tamper-evident audit trail

        Change one row, and the chain shows it.

        Each audit event stores a SHA-256 hash of its own content plus the previous event's hash. The runtime role can't update or delete rows, and a trigger refuses it anyway. Try rewriting history below. The hashes are computed live in your browser.

        Access model

        Five roles, four levels, set per connection.

        Workspace roles set the default. Each member can then get none, read, write or admin on each connection. SSO groups from OIDC or SAML can map to both.

        Deploy

        Up in five minutes, on Docker or Kubernetes.

        One image serves the web app and the API on port 8080, runs as a non-root user and exposes a health check. Migrations run automatically at start-up.

        Docker

        docker build -t comb:1.5.0 .
docker run -d --name comb -p 8080:8080 -v comb-data:/data \
  -e COMB_DATABASE_URL='postgres://comb_app:…@db:5432/comb_meta' \
  -e COMB_MIGRATION_DATABASE_URL='postgres://comb_owner:…@db:5432/comb_meta' \
  -e COMB_MASTER_KEY="$(openssl rand -base64 32)" \
  -e COMB_PUBLIC_URL='https://comb.example.com' \
  comb:1.5.0

        Helm

        helm install comb deploy/helm/comb \
  --set publicUrl=https://comb.example.com \
  --set trustProxy=10.0.12.34/32

        What you need

        Runtime
        Node.js 24, or the provided image
        Metadata
        One PostgreSQL database (16 recommended)
        Targets
        PostgreSQL 13 to 17
        Backups
        pg_dump included, pgBackRest optional
        Identity
        Passwords with TOTP, or OIDC and SAML
        Optional
        Patroni, SMTP, Slack, Teams, PagerDuty, Datadog

        Back up the metadata database and COMB_MASTER_KEY together. One is useless without the other.
