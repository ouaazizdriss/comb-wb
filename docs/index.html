The PostgreSQL workbench that reads every statement before your database does.

Comb is a query editor, data grid and ERD with approvals, column masking, a tamper-evident audit trail, monitoring and backups built in. It runs on your servers, it is free, and it never phones home.

Safe on production by default

Read-only connections, typed confirmation for DROP and TRUNCATE, and a second person for writes where you require it.

The server decides

Every rule runs in the Comb server. The browser only shows what the server already allows.

Every action is recorded

The audit trail is append-only and hash-chained, so a changed or deleted row is detectable.

Credentials stay server-side

Passwords, SSH keys and tokens are encrypted with AES-256-GCM and never reach the browser.

Every statement gets a plan before it gets a database.

Comb parses SQL with PostgreSQL's own parser, then runs it through eight checks in a fixed order. Pick a connection, an access level and a statement to see the plan. The rules here are the server's own.

Built for people who live in a SQL editor.

Keyboard first: ⌘K opens anything, ⌘↵ runs the statement under the cursor. These are real screens from a local install on the bundled shop demo database.

    comb=> \dn+

    One tool instead of six.

    A SQL client, a migration tool, a scheduler, a monitoring dashboard, an audit export and the spreadsheet of who has access. Comb ships them together, under one permission model and one audit trail.

    For developers
    • ⌘K jumps to any table, saved query or screen.
    • Grid edits are staged, shown as SQL, then applied in one transaction.
    • Autocomplete from the live catalog, error positions, notices and CSV export.
    • Versioned migrations with dry runs, drift detection and rollback.
    • Cron-scheduled SQL with retries, delivered to Slack, Teams or a webhook.
    For managers and security
    • Every statement, login and change, with before and after images of each written row.
    • Four-eyes approvals on the connections you choose, after a rolled-back dry run.
    • PII classification and masking applied on the server to results, exports and the audit trail.
    • Compliance controls with evidence, data-subject requests and retention policies.
    • Usage and cost by team, with a chargeback CSV.
    comb=> \conninfo

    One process and one metadata database. Nothing else to run.

    No broker, no cache

    Background work runs on pg-boss, a queue that lives in the metadata database. There is no Redis to operate.

    A real parser, not regexes

    Statements are classified with libpg-query, PostgreSQL's own parser, so comments, quoting and casing can't hide a DROP.

    Your role is the ceiling

    Comb only narrows what the stored database user may do, never widens it. Give each connection a least-privilege role.

    comb=> SELECT id, at, event, prev_hash, hash FROM audit_events ORDER BY id;

    Change one row, and the chain gives it away.

    Each event stores a SHA-256 hash of its content and of the previous event's hash. The runtime role can't update or delete rows, and a trigger refuses it anyway. Rewrite history below: the hashes are computed live in your browser.

    Running in five minutes on Docker or Kubernetes.

    One image serves the web app and the API on port 8080, runs as a non-root user and exposes a health check. Migrations run on start-up.

    Docker

    docker build -t comb:1.5.0 .
docker run -d --name comb -p 8080:8080 -v comb-data:/data \
  -e COMB_DATABASE_URL='postgres://comb_app:…@db:5432/comb_meta' \
  -e COMB_MIGRATION_DATABASE_URL='postgres://comb_owner:…@db:5432/comb_meta' \
  -e COMB_MASTER_KEY="$(openssl rand -base64 32)" \
  -e COMB_PUBLIC_URL='https://comb.example.com' \
  comb:1.5.0

    Helm

    helm install comb deploy/helm/comb \
  --set publicUrl=https://comb.example.com \
  --set trustProxy=10.0.12.34/32

    What you need

    runtime
    Node.js 24, or the provided image
    metadata
    One PostgreSQL database, 16 recommended
    targets
    PostgreSQL 13 to 17
    backups
    pg_dump included, pgBackRest optional
    identity
    Passwords with TOTP, or OIDC and SAML
    optional
    Patroni, SMTP, Slack, Teams, PagerDuty, Datadog

    Back up two things together: the metadata database and COMB_MASTER_KEY. One is useless without the other.
